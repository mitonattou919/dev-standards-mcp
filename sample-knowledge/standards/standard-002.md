# コミットメッセージ規約

## 基本方針

コミットメッセージは「何を変更したか」ではなく「なぜ変更したか」を主に書く。
「何を」はdiffを見れば分かるが、「なぜ」はコード自体には残らない。

## フォーマット

```
<type>: <一行要約（50文字程度）>

<本文（必要な場合のみ）— なぜこの変更が必要だったか>
```

### type一覧

| type       | 用途                         |
|------------|------------------------------|
| `feat`     | 新機能の追加                  |
| `fix`      | バグ修正                     |
| `refactor` | 挙動を変えないコード整理       |
| `test`     | テストの追加・修正             |
| `docs`     | ドキュメントのみの変更          |
| `chore`    | ビルド設定・依存関係更新など    |

## 良い例・悪い例

**悪い例**

```
fix: バグ修正
```

**良い例**

```
fix: 検索結果のスコア降順ソートが逆になっていたのを修正

BM25スコアの比較演算子が逆になっており、関連度の低い結果が
上位に表示されていた。
```

## クイックリファレンス

| 項目             | ルール                          |
|-----------------|---------------------------------|
| 一行要約の長さ     | 50文字程度                       |
| 本文で書くこと     | 「なぜ」その変更が必要だったか       |
| 本文で書かないこと | 「何を」変更したか（diffで分かる）  |
